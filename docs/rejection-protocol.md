# Candidate rejection diagnostic protocol

I use the existing two-stage selection from `e91a55f`, including the hybrid detector, .40 threshold, three-tick gap and six-tick minimum. I will verify the component hashes and reproduce the ordered validation proposals by source. The diagnostic entry point accepts only training and validation. I use the 16 training participants and four validation participants. The four validation people previously contributed to the choice of detector and CNN, so this is development evidence.

**Units.** I assign proposals to references once using descending-IoU, class-blind one-to-one matching at .50 in original frame coordinates. A matched proposal inherits the reference class. An unmatched proposal counts as an incorrect acceptance regardless of its four-way guess. I separately mark partial overlaps and verified zero-overlap negatives. The latter require full coverage by original annotations outside the four target labels. True but unproposed gestures enter the separate stream metric. Oracle boundaries serve only in the paired alignment diagnostic.

**Comparisons.** I keep the frozen CNN's four-way top label for all comparisons. I test the original .60 cutoff, unconditional acceptance, a scalar cutoff (.35/.45/.60/.75/.85), conditional temperature scaling at the original .60 cutoff, per-predicted-class cutoffs from the same grid, a top-two probability margin (0/.10/.20/.30/.40/.50), and the original five-way CNN with its background logit restored. The five-way method accepts a winning target above its selected joint-probability cutoff (0/.20/.35/.45/.60). I fit temperature by minimum four-class NLL on matched calibration candidates over 81 log-spaced values from .25 to 4. I choose operating thresholds by candidate micro F1, then fewer false positives, then proximity to the default cutoff (.60 for probabilities, .20 for margins). A class with no matched positive or no correct top prediction in the calibration fold uses that fold's global threshold.

**One possible new head.** I permit one binary logistic target-presence gate, with the same four-way classifier, if training has at least 16 matched positives and 16 verified zero-overlap negatives, each spanning four or more participants, and unconditional acceptance admits verified validation negatives. I use the existing 20-dimensional pooled visual/flow logit descriptor. I fit on matched positives and verified zero-overlap training proposals, with training-only standardization, balanced binary loss and fixed L2 penalty .05. I exclude partial overlaps from fitting. The target joint scores are the gate output times the unchanged conditional class probabilities. I compare this gate and the restored background logit with identical rejection rules, including an untrained constant-presence control from the eligible training class frequency. These comparisons test discrimination gained from proposal-specific background evidence. Class balancing and proposal selection can change probability calibration.

**Validation and stopping.** I leave one validation participant out at a time when fitting temperature or thresholds, then concatenate predictions for the four excluded participants. No proposal from a scored participant contributes to the calibration parameters for that fold. I report fixed-baseline train/validation distributions, matched-only NLL, equal-width five-bin ECE, Brier score and reliability for whether a candidate's top target label is a correct localized event. I report threshold sweeps and confusion matrices with unmatched/rejected in index zero. I measure conditional recognition, precision, recall, candidate micro F1 and full-stream F1@.50 separately.

I call a change meaningful for this diagnostic if it adds at least two correct matched validation proposals, improves candidate F1 by at least .05, gains correct proposals on at least two validation participants, and increases stream false alarms by at most .25/min relative to the released rule. Among passing variants I freeze the highest candidate F1, breaking ties by fewer false positives and then comparison order. A passing rule is refit on all validation participants for a future independent evaluation. If none passes I retain the existing rule and stop. I will report descriptive changes even when they fall short. I will not run the old test cohort, expand the architecture search or update the app in this study.
