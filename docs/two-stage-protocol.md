# Separating target detection and classification

I keep the 56-source IPN split and the four labels fixed. Each source remains continuous, with other gestures and idle frames retained. I reuse the frozen encoder, cache and seed-17 heads from local release 37ebe94. I use the 32 training streams for fitting, the eight validation streams for design and selection, then the 16 test streams for one locked comparison. The original experiment already exposed the aggregate test failure. This follow-up is a paired re-evaluation on eight previously studied test participants. A fresh external cohort would provide stronger confirmation.

I ask whether a separate target detector improves class-aware segment F1 at IoU .50 over the frozen five-way decoder. A positive point estimate with a paired participant-bootstrap 95% interval above zero supports improvement on this cohort. I also require the false-alarm rate to be reported alongside recall. Known-boundary classification and exact full-stream lists are separate outcomes.

I compare smoothed Farnebäck energy with a binary regularized logistic detector on 5- and 15-tick averages of the same motion features. The binary target means one of the four supported actions. Other annotated actions are negatives. I search short gaps, minimum durations and score thresholds on validation. I select class-agnostic F1@.50, then F1@.25, then fewer false alarms. I compare three classifiers on the same proposed intervals: the frozen visual CNN, the frozen flow logistic model and four-way learned fusion of both heads' logits pooled over each half. I fit fusion on training bouts only. Each classifier can reject a candidate with its own validation-selected minimum four-way score. I select by class-aware validation segment F1@.50, then @.25 and then fewer false alarms. I freeze the choices and checkpoint digests in Git before opening test caches for this study.

I report candidate recall without class labels, class-aware segment F1 at .10/.25/.50, macro F1 across the four classes both within known windows and for localized events at .50, unmatched detections per nominal minute, endpoint MAE only for matched intervals and exact lists on uninterrupted recordings. All methods use the original 30 fps frame annotations for scoring. The 7.5 Hz inference path receives only image and motion observations. I examine the old detector's fragmentation, background and opposite-direction mistakes, missed intervals, score reliability and signed endpoint offsets. An edge-of-image motion proxy cannot distinguish cameras, people or lighting. I report how well differences between ordered DINO embeddings predict opposite directions before drawing conclusions about this representation.

### Validation amendment before the test lock

On the four validation participants the binary motion detector produced 9.13 false proposals/min at its best validation F1@.50. I saved this first comparison in `motion-development.json`. I added one prespecified family for the final search, a 299-parameter binary logistic detector which appends the five frozen visual logits averaged over the same two windows. Its thresholds are .25, .40, .55, .70, .85, .90 and .95. Motion-only logistic thresholds use the first five of these. The energy detector uses four quantiles (.70/.80/.90/.95) of training non-target energy. All allow gaps of 1, 3 or 6 ticks and require at least 3 or 6 ticks after merging. Classifier thresholds are 0, .45, .60, .75 and .85. Exact ranking ties retain the first listed model/setting. I made this amendment before evaluating any new model on test.

I used Codex assistance for this local investigation. The test comparison, app checks and training records are separate from the original release.
